## ADDED Requirements

### Requirement: 登录页

前端 SHALL 提供 `/login` 页面，包含邮箱与密码输入、提交按钮、错误提示与跳转注册页入口；提交成功后将用户跳转至默认落地页。

#### Scenario: 登录成功跳转
- **WHEN** 用户输入正确的邮箱与密码并提交
- **THEN** access token 写入内存中的认证状态
- **AND** 页面跳转到默认落地页（`/chat`），不出现整页刷新

#### Scenario: 登录失败就地提示
- **WHEN** 服务端返回 `401 / 20001`
- **THEN** 表单区域展示中文错误提示，输入内容保留，页面不跳转

#### Scenario: 提交中防重复
- **WHEN** 用户点击提交且请求尚未返回
- **THEN** 提交按钮进入加载态并禁用，避免重复提交

### Requirement: 注册页

前端 SHALL 提供 `/register` 页面，在提交前做邮箱格式与密码长度（8–64）校验，服务端返回错误码时给出对应提示。

#### Scenario: 本地校验先于网络请求
- **WHEN** 用户输入非法邮箱即提交
- **THEN** 前端直接展示字段级错误，不发起网络请求

#### Scenario: 邮箱已被占用
- **WHEN** 服务端返回 `409 / 40901`
- **THEN** 在邮箱输入项下方展示「该邮箱已注册」并给出前往登录的入口

### Requirement: 认证态仅驻留内存并可启动恢复

前端 SHALL 仅将 access token 保存在内存状态中，MUST NOT 写入 `localStorage`、`sessionStorage` 或可读 Cookie；页面刷新后 SHALL 通过 refresh Cookie 静默恢复登录态。

#### Scenario: 刷新页面后自动恢复
- **WHEN** 已登录用户刷新浏览器页面
- **THEN** 应用启动时调用刷新接口换取新 access token 并恢复用户信息
- **AND** 恢复期间受保护路由显示加载态而非闪跳到登录页

#### Scenario: 令牌不落本地存储
- **WHEN** 登录成功后检查浏览器本地存储
- **THEN** `localStorage` 与 `sessionStorage` 中不存在 access token 或 refresh token

#### Scenario: 无法恢复时回到登录页
- **WHEN** 启动恢复时刷新接口返回 `401`
- **THEN** 清空认证状态并跳转 `/login`，记录原始目标路径以便登录后返回

### Requirement: 静默刷新采用单飞与请求重放

前端 SHALL 在收到 `401 / 20002` 时发起静默刷新；同一时刻的多个 401 MUST 复用同一次刷新请求，刷新成功后自动重放原请求一次，重放请求 MUST NOT 再次触发刷新。

#### Scenario: 并发 401 只刷新一次
- **WHEN** 三个受保护请求同时返回 `401 / 20002`
- **THEN** 只发出一次刷新请求
- **AND** 三个原请求在刷新成功后各被重放一次并成功

#### Scenario: 刷新失败统一登出
- **WHEN** 刷新接口返回 `401 / 20003` 或 `401 / 20004`
- **THEN** 清空认证状态、跳转登录页，且不再重放原请求

#### Scenario: 刷新接口自身不触发刷新
- **WHEN** 刷新请求本身返回 401
- **THEN** 不产生新的刷新请求（无递归），直接走登出流程

### Requirement: 路由鉴权与角色守卫

前端 SHALL 在路由层校验登录态与角色：未登录访问受保护路由跳转登录页并记录目标路径；非 `admin` 访问管理路由跳转到无权访问页。

#### Scenario: 未登录访问受保护路由
- **WHEN** 未登录用户直接访问 `/chat`
- **THEN** 重定向到 `/login`，登录成功后返回 `/chat`

#### Scenario: 普通用户访问管理路由
- **WHEN** 普通用户访问 `/admin/users`
- **THEN** 不渲染管理页面内容，跳转到无权访问提示页

### Requirement: 错误码到用户提示的映射

前端 SHALL 以业务码（而非 HTTP 状态码或 `message` 字符串）决定用户提示与行为，映射表来自共享契约包；未识别的业务码 SHALL 展示通用错误提示并附 `requestId`。

#### Scenario: 已知业务码展示专用文案
- **WHEN** 服务端返回 `code: 42901`
- **THEN** 页面展示「请求过于频繁，请稍后再试」，而不是服务端的原始 `message` 拼接

#### Scenario: 未知业务码可排障
- **WHEN** 服务端返回映射表中不存在的业务码
- **THEN** 展示通用失败提示，并在提示中可展开查看 `requestId`

### Requirement: 登出

前端 SHALL 提供登出入口，调用登出接口后清空认证状态并跳转登录页；无论接口成功与否，本地状态 MUST 被清空。

#### Scenario: 登出后无法访问受保护路由
- **WHEN** 用户点击登出
- **THEN** 调用登出接口并清空内存中的令牌与用户信息
- **AND** 随后访问 `/chat` 会被重定向到 `/login`

#### Scenario: 登出接口失败仍完成本地登出
- **WHEN** 登出接口因网络错误未能成功
- **THEN** 本地认证状态仍被清空并跳转登录页，同时提示「已退出本地登录」
