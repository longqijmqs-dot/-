# 后端 / 前端 命令手册

> 适用项目：AI 对话平台（`ai-chat-platform`）
> 命令均直接抄录自各 `package.json` 的 `scripts`，与仓库代码一致。
> 更新时间：2026-10-29

---

## 0. 前置条件

| 条件 | 说明 |
|---|---|
| Node.js ≥ 22 | `engines` 要求 |
| pnpm 11.28.5 | `packageManager` 锁定版本（可用 `corepack enable` 激活） |
| WSL2 + Docker | MySQL / Redis 跑在容器里；应用在 Windows 侧热重载 |
| 环境变量 | 根目录复制 `.env.example` → `.env`，并同步到 `apps/api/.env` |
| 契约包 | `apps/api`、`apps/web` 都依赖 `@app/contract` 的 `dist` 产物，**必须先构建**（根脚本已内置，手动执行时注意） |

启动依赖服务（WSL 终端，`sudo`）：

```bash
cd /mnt/c/Users/33281/Desktop/测试
sudo docker compose -f compose.dev.yaml up -d      # 仅 MySQL + Redis（本地开发用）
sudo docker compose up -d                           # 本地开发用 compose.dev.yaml；全栈编排用 compose.yaml
sudo docker compose ps                              # 两个容器应显示 healthy
```

> ⚠️ 注意：`compose.dev.yaml` 只起依赖；`compose.yaml` 会连 api/web 一起起。开发时用前者，避免端口冲突。

## 1. 根目录命令（共享 / 一键）

在项目根目录执行：

| 命令 | 作用 |
|---|---|
| `pnpm install` | 安装全部依赖（workspace 三个包） |
| `pnpm dev` | **构建契约包 + 同时启动前后端**（后端 3000，前端 5173） |
| `pnpm dev:api` | 构建契约包 + 启动后端（仅后端） |
| `pnpm dev:web` | 构建契约包 + 启动前端（仅前端） |
| `pnpm build:contract` | 构建契约包（产出 `dist/cjs` + `dist/esm`） |
| `pnpm build:api` | 构建契约包 + 后端生产构建（输出 `apps/api/dist`） |
| `pnpm build:web` | 构建契约包 + 前端生产构建（输出 `apps/web/dist`） |
| `pnpm start:api` | 启动已构建的后端（`node apps/api/dist/main.js`） |
| `pnpm test` | 运行各包测试（契约单测 + 后端集成测试） |
| `pnpm typecheck` | 全量类型检查（contract / api / web） |
| `pnpm db:generate` | Prisma 生成客户端 |
| `pnpm db:migrate` | Prisma 迁移（开发环境，会要求起迁移名） |
| `pnpm db:studio` | 打开 Prisma Studio |
| `pnpm db:seed` | 写入角色 + 管理员种子数据 |

**最常用组合**（日常开发）：

```bash
pnpm install            # 首次
sudo docker compose -f compose.dev.yaml up -d   # 起 MySQL / Redis
pnpm db:migrate         # 首次：输入迁移名 init
pnpm db:seed            # 建 admin / user 角色 + 管理员
pnpm dev                # 一键起前后端
```

## 2. 后端指令（`apps/api`，`@app/api`）

进入目录：`cd apps/api`；或统一用 `pnpm --filter @app/api <脚本>`。

### 2.1 开发

| 命令 | 等价脚本 | 说明 |
|---|---|---|
| `pnpm --filter @app/api start:dev` | `nest start --watch` | 热重载启动，监听 `http://localhost:3000` |
| `pnpm dev:api`（根目录） | 同上，但**先构建契约包** | 推荐用这个，避免契约包未构建导致 500 / 白屏 |

启动后可访问：

- Swagger：`http://localhost:3000/api/docs`
- 健康检查：`http://localhost:3000/api/health`

### 2.2 构建与启动

| 命令 | 等价脚本 | 说明 |
|---|---|---|
| `pnpm --filter @app/api build` | `tsc -p tsconfig.build.json` | 编译到 `apps/api/dist`（CommonJS） |
| `pnpm --filter @app/api start` | `node dist/main.js` | 运行已构建产物（生产） |
| `pnpm --filter @app/api start:prod` | `node dist/main.js` | 同上 |

> ⚠️ 构建顺序必须是 **contract → prisma generate → api build**。若 `tsc` 报 `Cannot find module '.prisma/client'`，说明 Prisma 客户端还没生成，先执行 `pnpm db:generate`。

### 2.3 测试与类型检查

| 命令 | 等价脚本 | 说明 |
|---|---|---|
| `pnpm --filter @app/api test` | `jest --runInBand` | 后端集成测试（supertest 打真实 HTTP） |
| `pnpm --filter @app/api typecheck` | `tsc -p tsconfig.json --noEmit` | 仅类型检查 |

> ⚠️ 后端测试**依赖真实 MySQL + Redis**：
> - `test/global-setup.ts` 会用 `wsl -u root -e mysql` 创建 `ai_chat_test` 库并跑迁移、seed；
> - 测试库连接串与账号写在 `test/helpers.ts` / `global-setup.ts` 中（当前为硬编码，见「已知问题」）；
> - 必须串行执行（`maxWorkers: 1`），否则并发写测试库会冲突。
> - 若提示连不上 `localhost:3306`，先确认 Docker 容器 healthy。

### 2.4 数据库（Prisma）

| 命令 | 等价脚本 | 说明 |
|---|---|---|
| `pnpm --filter @app/api prisma:generate` | `prisma generate` | 依据 `schema.prisma` 生成客户端 |
| `pnpm --filter @app/api prisma:migrate` | `prisma migrate dev` | 开发迁移（首次要求输入迁移名，如 `init`） |
| `pnpm --filter @app/api prisma:studio` | `prisma studio` | 可视化查看数据 |
| `pnpm --filter @app/api db:seed` | `ts-node prisma/seed.ts` | 写入 `admin` / `user` 角色 + 管理员账号 |

> ⚠️ `prisma migrate dev` 会创建**影子数据库**做 diff，因此数据库账号需要 `CREATE/DROP` 权限；生产环境应拆成 `app`（读写）与 `migrator`（建表改表）两个账号。

### 2.5 后端环境变量（`.env`）

后端启动时会用 zod 校验（`apps/api/src/config/env.ts`），**缺关键变量会直接启动失败并打印缺哪个**。配置加载顺序：`apps/api/.env.local` → `apps/api/.env` → 仓库根 `.env`。

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `NODE_ENV` | 否 | `development` | `development` / `test` / `production` |
| `PORT` | 否 | `3000` | 监听端口 |
| `DATABASE_URL` | ✅ | — | MySQL 连接串 |
| `REDIS_URL` | ✅ | — | Redis 连接串 |
| `JWT_ACCESS_SECRET` | ✅ | — | access 密钥，至少 32 位 |
| `JWT_ACCESS_TTL` | 否 | `15m` | access 有效期 |
| `JWT_REFRESH_SECRET` | ✅ | — | refresh 密钥，至少 32 位 |
| `JWT_REFRESH_TTL` | 否 | `7d` | refresh 有效期 |
| `BCRYPT_ROUNDS` | 否 | `12` | bcrypt 成本因子（生产 ≥ 10） |
| `CORS_ORIGIN` | 否 | `http://localhost:5173` | 允许的跨域来源 |
| `UPLOADS_DIR` | 否 | 仓库根 `uploads/` | 上传文件目录（建议绝对路径） |
| `UPLOAD_MAX_SIZE` | 否 | `10485760`（10MB） | 单文件上限 |
| `AI_PROVIDER` | 否 | `mock` | `mock`（假流） / `deepseek`（真实） |
| `DEEPSEEK_API_KEY` | deepseek 必填 | — | DeepSeek API Key |
| `DEEPSEEK_BASE_URL` | 否 | `https://api.deepseek.com` | DeepSeek 地址 |
| `DEEPSEEK_MODEL` | 否 | `deepseek-chat` | 模型名 |
| `AI_TIMEOUT_MS` | 否 | `60000` | 上游超时 |
| `AI_CONTEXT_MESSAGES` | 否 | `20` | 送入模型的上下文条数 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | seed 用 | `admin@example.com` / `Admin@123456` | 种子管理员账号（未设时用默认弱口令） |

`.env.example` 里还有 MySQL / Redis 容器相关变量：`MYSQL_ROOT_PASSWORD`、`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`、`REDIS_PASSWORD`。

## 3. 前端指令（`apps/web`，`@app/web`）

进入目录：`cd apps/web`；或统一用 `pnpm --filter @app/web <脚本>`。

| 命令 | 等价脚本 | 说明 |
|---|---|---|
| `pnpm --filter @app/web dev` | `vite` | 启动开发服务器，`http://localhost:5173` |
| `pnpm --filter @app/web build` | `vue-tsc --noEmit && vite build` | 类型检查 + 生产构建到 `apps/web/dist` |
| `pnpm --filter @app/web preview` | `vite preview` | 本地预览生产构建 |
| `pnpm --filter @app/web typecheck` | `vue-tsc --noEmit` | 仅类型检查 |

> ⚠️ 前端**没有**独立测试脚本（`package.json` 里没有 `test`），前端单测待补。`pnpm test`（根）只跑契约包与后端。

### 3.1 前端环境变量

前端默认**不需要** `.env`：开发时通过 Vite 代理把 `/api` 转发到 `http://localhost:3000`（见 `apps/web/vite.config.ts`），从而与后端同源，保证 httpOnly Cookie 能带上。

- 若需要自定义，可用 `VITE_` 前缀的变量（如 `VITE_API_BASE`），并在代码里 `import.meta.env.VITE_*` 读取。
- 生产部署由 Nginx 反向代理 `/api`，前端构建产物不含密钥。

### 3.2 前端访问入口

- 对话页：`http://localhost:5173/chat`（登录后）
- 登录：`http://localhost:5173/login`
- 注册：`http://localhost:5173/register`
- 后台：`http://localhost:5173/admin`（仅 admin 角色）

## 4. 契约包指令（`packages/contract`，`@app/contract`）

前后端共享的 zod 契约，通常不需要单独操作（根脚本已内置构建）。

| 命令 | 等价脚本 | 说明 |
|---|---|---|
| `pnpm --filter @app/contract build` | `tsc -p tsconfig.build.cjs.json && tsc -p tsconfig.build.esm.json && node scripts/emit-module-type.mjs` | 产出 CJS（给 NestJS）+ ESM（给 Vite） |
| `pnpm --filter @app/contract test` | `jest --runInBand` | 契约单测（信封 / 错误码 / 分页 / 认证 / SSE 事件） |
| `pnpm --filter @app/contract typecheck` | `tsc -p tsconfig.test.json --noEmit` | 仅类型检查 |

> ⚠️ 前端白屏、控制台报找不到 `@app/contract`，通常是契约包没构建。执行 `pnpm build:contract` 后重启 dev 即可。

## 5. 依赖服务指令（MySQL / Redis）

```bash
# 启动依赖（WSL 内，需 sudo）
sudo docker compose -f compose.dev.yaml up -d

# 查看状态（应为 healthy）
sudo docker compose ps

# 停止 / 重启
sudo docker compose -f compose.dev.yaml down
sudo docker compose -f compose.dev.yaml restart

# 查看日志
sudo docker compose -f compose.dev.yaml logs -f mysql
sudo docker compose -f compose.dev.yaml logs -f redis

# 全栈编排（含 api + web）
sudo docker compose up -d
sudo docker compose ps
```

## 6. 部署指令

```bash
# 本地：构建镜像 + 起全栈容器
./deploy/deploy.sh

# 远程：构建镜像 + 推送服务器（需先设置 REMOTE_HOST）
REMOTE_HOST=user@your-server ./deploy/deploy.sh --remote

# 或手动
docker compose build api
docker compose build web
docker compose up -d
```

- 部署产物：前端 Nginx（`Dockerfile.web`）+ 后端 Node（`Dockerfile.api`，多阶段构建）。
- Nginx 已配置 SSE 关闭缓冲（`proxy_buffering off`）、上传上限 12m、SPA fallback。
- 生产环境必须配 HTTPS（Let's Encrypt），`deploy/README.md` 有完整步骤。

```bash

```

```bash

```

### 7.4 全量质量检查

```bash

pnpm build          # 或 pnpm build:api / pnpm build:web（注意根目录无 build 脚本，用 build:api / build:web）

```


## 8. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 前端白屏 / 报找不到 `@app/contract` | 契约包未构建 | `pnpm build:contract` 后重启 dev |
| 接口全部 500 / 日志报连不上数据库 | 容器没起 | `sudo docker compose -f compose.dev.yaml up -d`，等 healthy |
| 登录返回 429 | 触发限流（5 次/分钟/IP） | 等 60 秒 |
| 页面提示「账号已被禁用」 | 管理员禁用标记 | 清除 Redis `user:disabled:<id>` 或在后台重新启用 |
| `pnpm db:migrate` 报 P3014 影子库无权限 | 账号缺建库权限 | 给应用账号授予 `CREATE/DROP`，或改用专用迁移账号 |
| 上传大文件 413 | Nginx 默认 1MB 限制 | `nginx.conf` 已设 `client_max_body_size 12m` |
| SSE 不逐字输出 | 反代缓冲 | 确认 Nginx 有 `proxy_buffering off` 与 `X-Accel-Buffering: no` |
| `tsc` 报 `Cannot find module '.prisma/client'` | 未生成 Prisma 客户端 | `pnpm db:generate` |
| 后端测试失败 | 测试库未建 / 容器未起 | 确认 `ai_chat_test` 可建且 MySQL/Redis 正常 |

## 9. 已知问题（编写本手册时发现，建议修复）

1. **后台禁用用户参数未校验**：`apps/api/src/admin/admin.controller.ts` 中 `status === '1' ? 1 : 0`，任何非 `'1'` 的值（含缺省）都会**禁用**用户；契约里定义的 `UpdateUserStatusSchema` 未被使用。
2. **测试凭据硬编码**：`apps/api/test/helpers.ts`、`apps/api/test/global-setup.ts` 写死了测试库密码与管理员密码；`apps/api/prisma/seed.ts` 在未设 `ADMIN_PASSWORD` 时默认弱口令 `Admin@123456`。
3. **`deploy.sh --remote` 不完整**：只 scp 了 Dockerfile / nginx / compose / .env，未传源码与 lockfile，远程 `docker compose build` 会失败。
4. **上传路径校验可被前缀绕过**：`apps/api/src/uploads/uploads.service.ts` 用 `startsWith` 判断，存在 `uploads2/` 等兄弟目录时可越界。
5. **`pnpm build` 不存在**：根目录没有 `build` 脚本，只有 `build:contract` / `build:api` / `build:web`。
6. **版本不一致**：README/`.env.example` 写 MySQL 8.4，`compose.yaml` 用 `mysql:8.0`。
